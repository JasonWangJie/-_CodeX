# Fund Predictor 下一步优化建议

## 1. 先补齐“可验证性”（最高优先级）

1. 建立最小单元测试集（pytest）
   - `features/signals.py`：阈值边界、空值处理、`prob_fused` 单调性。
   - `backtest/simulator.py`：买卖配对、手续费、止盈/止损边界。
   - `backtest/walk_forward.py`：训练窗/验证窗切分、无交易窗口行为。
2. 增加回归测试样例
   - 用固定历史切片生成基准指标（trade_count、win_rate、max_drawdown），防止重构后策略漂移。
3. 在 CI 中加入基础检查
   - `pytest -q` + `python -m compileall fund_predictor`。

> 目标：把“能跑”升级为“可持续迭代且可证明正确”。

## 2. 提升“概率融合”质量（当前策略核心）

1. 对 `prob_reg` / `prob_cls` 做概率校准
   - 先做分箱可靠性图（reliability diagram），观察预测概率与真实命中率偏差。
   - 使用轻量校准（Platt/Isotonic 二选一）并留出时间切片防止泄漏。
2. 引入分市场状态的动态阈值
   - 震荡/下行市场提高 `min_signal_prob`，上行市场降低阈值以提升覆盖率。
3. 记录过滤损益归因
   - 统计“被过滤信号”的潜在收益、回撤、命中率，验证过滤是否真的增益。

> 目标：让概率不仅参与过滤，而且对收益-回撤权衡有可解释贡献。

## 3. 强化样本外评估（避免参数幻觉）

1. 从 walk-forward 扩展为嵌套验证
   - 外层评估、内层调参，避免同一窗口多次试错导致过拟合。
2. 引入参数稳定性评分
   - 统计相邻窗口最优参数跳变幅度；跳变过大时降权或触发“保守参数集”。
3. 增加交易成本敏感性分析
   - 手续费、滑点做区间扰动，输出策略脆弱性热力图。

## 4. 数据层与工程可靠性

1. 增量拉取链路加“质量门”
   - 缺失率、日期连续性、异常跳点（z-score）检测，不达标不入库。
2. 缓存一致性治理
   - 本地文件缓存与 SQLite 缓存增加版本号/校验和，避免脏读。
3. 错误分级与重试策略细化
   - 网络类可重试、解析类快速失败、数据质量类熔断告警。

## 5. 报告与可解释性输出

1. 新增“策略诊断页”
   - 概率分布、阈值命中曲线、各强度层收益贡献、过滤前后对比。
2. 输出“最近 N 窗口稳定性”
   - 展示最近窗口参数变化、胜率漂移、回撤变化，辅助人工决策。
3. 为交易管理器增加风险看板
   - 仓位集中度、单标的风险暴露、最大连续亏损天数。

## 6. 建议的两周落地顺序（可直接执行）

- 第 1–3 天：补齐单元测试与回归基线；接入 CI。
- 第 4–6 天：实现概率校准 + 可靠性图；落地过滤归因统计。
- 第 7–9 天：做嵌套 walk-forward 与参数稳定性评分。
- 第 10–12 天：报告诊断页与风险看板。
- 第 13–14 天：回归验收、参数冻结、发布说明。

---

如果资源有限，建议先做：**测试基线 > 概率校准 > 报告归因**。这三项对“稳定收益提升”和“避免回测幻觉”的性价比最高。
