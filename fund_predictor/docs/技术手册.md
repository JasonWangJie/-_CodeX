# 基金预测/回测系统技术手册

> 目标：给开发/维护人员提供“系统原理 + 关键实现 + 性能与准确率优化策略”的技术说明。  
> 原则：在保证可维护、可复现、可高性能执行的前提下，逐步提升预测有效性。

---

## 1. 技术架构总览

系统按分层设计：

1. **数据层（data/）**
   - `fetcher.py`：拉取天天基金历史净值，支持重试与增量更新；
   - `parser.py`：解析接口返回的 HTML/JS 片段；
   - `storage.py`：本地 parquet/csv 存取。

2. **特征层（features/）**
   - `indicators.py`：计算 R1、R2、HV、加速度、动态分位阈值；
   - `signals.py`：基于阈值与加速度生成信号与强度。

3. **回测层（backtest/）**
   - `simulator.py`：交易模拟（买入延迟、持有期、动态止盈）；
   - `grid_search.py`：参数网格扫描；
   - `scoring.py`：组合评分与惩罚；
   - `walk_forward.py`：滚动验证与调参历史。

4. **应用层（cli/report/trade）**
   - `cli.py`：命令入口和交互控制台；
   - `report/`：输出 md/html/json/csv 报告；
   - `trade/manager.py`：本地持仓、交易流水、收益统计、撤销。

---

## 2. 执行流程（analyze）

`analyze` 默认流程：

1. 读取基金列表（命令行 > fund-file > funds.json）；
2. 单基金拉取/更新净值；
3. 计算指标与信号；
4. 阈值+M/N 网格回测；
5. 生成排名与报告；
6. 写入抓取状态与调参历史。

失败隔离策略：
- 单基金失败不影响其他基金；
- 失败基金写入状态并从排名中剔除。

---

## 3. 数据与文件约定

关键文件：
- `config.yaml`：运行参数；
- `data/meta/funds.json`：基金池；
- `data/nav/*.parquet`：净值缓存；
- `data/meta/fetch_status.json`：抓取状态；
- `data/meta/tuning_history.jsonl`：滚动调参历史；
- `data/meta/portfolio.json`：本地交易账本；
- `output/reports/*`：分析报告。

---

## 4. 性能与稳定性策略（当前）

1. 增量更新减少网络和解析开销；
2. 网格组合超过阈值时自动切换精简网格；
3. 单基金失败隔离，避免批次整体失败；
4. 文本表格输出避免增加重依赖；
5. 默认不启用多进程，降低环境不确定性。

---

## 5. 在“轻量高性能”约束下提升预测准确率的建议

以下策略遵循三个约束：
- 不引入重型框架；
- 不显著增加运行时长；
- 不降低稳定性。

### 当前版本已落地（v1.1）

1. 趋势过滤（短均线/长均线）；  
2. 信号强度分层；  
3. 近期窗口加权；  
4. 交易成本与滑点；  
5. 数据质量过滤。  

### 建议 A：做“市场状态过滤”而不是复杂模型

思路：
- 当市场处于明显下行趋势时，降低或屏蔽抄底信号；
- 当市场中性/回暖时，恢复信号。

实现（轻量）：
- 增加一个指数过滤开关（例如沪深300趋势）；
- 用简单均线趋势判定，不引入新训练过程。

收益：
- 常能减少“逆势抄底”带来的连续亏损。

### 建议 B：对信号强度做分层阈值

思路：
- 不同强度信号对应不同仓位建议/不同持有期；
- 弱信号减少触发，强信号重点关注。

实现（轻量）：
- 在现有 `signal_intensity` 基础上增加层级映射表；
- 回测时按层级统计命中率和收益分布。

收益：
- 可以提升整体盈亏比，而非单纯追求信号数量。

### 建议 C：增加“最近窗口优先”的参数稳定性约束

思路：
- 参数不只看全历史最优，还要看最近窗口是否仍有效；
- 对“近期明显失效”的参数降权。

实现（轻量）：
- 复用现有 walk-forward 结果；
- 在评分中提高 recent_validation 权重或加失效惩罚。

收益：
- 可降低参数漂移导致的实时失真。

### 建议 D：引入交易成本与滑点（可配置）

思路：
- 回测收益若不扣除成本，容易高估；
- 尤其短周期策略，对成本更敏感。

实现（轻量）：
- 在 simulator 增加固定费率/滑点参数；
- 默认可设为0，按需开启。

收益：
- 让结果更接近真实执行表现。

### 建议 E：加强样本质量过滤

思路：
- 对缺失严重、净值异常跳变基金降低权重或剔除；
- 避免坏数据污染参数搜索。

实现（轻量）：
- 增加数据质量评分（缺失率、异常值比例）；
- 评分低于阈值则跳过该基金的参数寻优。

收益：
- 通常能显著改善策略稳定性。

---

## 6. 不建议的方向（当前阶段）

为保持项目高性能与低失败率，当前不建议：

1. 引入深度学习框架（训练/依赖/环境复杂度显著上升）；
2. 做超大规模全参数暴力搜索（执行时长不稳定）；
3. 加入过多外部数据源（接口稳定性与可复现性下降）。

---

## 7. 推荐迭代顺序（性价比最高）

1. 市场状态过滤（低成本、高收益）；
2. 强度分层 + 分层回测统计；
3. 成本/滑点建模；
4. 数据质量评分；
5. 适度增强 walk-forward 稳定性约束。

---

## 8. 技术维护建议

1. 每次改动后至少执行：
   - `python -m compileall fund_predictor`
2. 保持配置向后兼容（新增项给默认值）；
3. 所有新字段在手册中同步更新；
4. 避免把业务逻辑散落在 CLI，尽量收敛到模块函数。
